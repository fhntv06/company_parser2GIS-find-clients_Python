# Источники данных

Источник отвечает на один вопрос: какие организации есть в городе и какой у них сайт. Дальше всё одинаково для любого
источника: нормализация адреса сайта, дедуп по домену, проверка доступности, база.

## Сравнение

| Источник | Цена | Сайт и телефон | Покрытие | Юридически |
|---|---|---|---|---|
| **Overture Maps** (по умолчанию) | бесплатно | да, у части мест | в Казани у 58% мест (5 900 из 10 081) есть сайт | лицензия CDLA-Permissive 2.0, нужно указывать источник при публикации данных |
| **2GIS Places API** | платный тариф | только на тарифе с контактами | самое полное | условия хранения данных уточнять у 2GIS |
| **Свой CSV** (Чекко, Контур, Excel) | как у поставщика | как в файле | зависит от поставщика | по условиям поставщика |

## Overture Maps

Открытая база мест (данные Meta, Microsoft и других). Система делает так:
город → рамка (Nominatim) → `overturemaps download` → фильтр по теме (duckdb) → CSV → импорт.
Файлы кэшируются в `data/overture/` на 30 дней (`overture_cache_days`).

Ограничения:
- Данные не всегда свежие: часть мест закрыта, часть сайтов мёртвая. Проверка доступности это отсеивает.
- Рамка города прямоугольная и захватывает окрестности.
- Категории английские и грубые; нецелевые места (лаборатории, рентген-центры) приходится отсеивать вручную.
- Полнота зависит от города и отрасли. Замерьте на своих данных: `python -m dgis overture --city ... --preset ...`, затем `stats`.

## 2GIS Places API

`python -m dgis run --cities "Казань" --rubrics "Стоматологии"`, нужен `DGIS_KEY` в `.env`.

Что выяснили на практике:
- **Демо-ключ контакты не отдаёт**: в ответе только `id`, название, адрес, рубрики. Поля `contact_groups` (сайт, телефон) нет ни в поиске, ни в карточке по id, ни на других доменах и параметрах. Для рабочей базы нужен тариф с контактами: уточните его у поддержки платформы 2GIS.
- Максимальный `page_size` для демо-ключа равен 10.
- В поле `value` контакта лежит редирект `link.2gis.ru/...`, настоящий адрес в `url`; код это учитывает.
- Глубина выдачи на один запрос ограничена, дробления по районам пока нет.

Диагностика ключа: `python -m dgis probe`.

## Свой CSV

`python -m dgis import файл.csv --city "Казань" --rubric "Стоматологии" --tag src1`

Колонки (регистр не важен, нужна только колонка с сайтом):

| Колонка | Синонимы | Примечание |
|---|---|---|
| `websites` | `website`, `url`, `site` | несколько значений через `\|` или `;` |
| `name` | `title` | |
| `address` | | |
| `phones` | `phone` | несколько через `\|` |
| `category` | `rubric` | если пусто, берётся из `--rubric` |
| `city` | | если пусто, берётся из `--city` |
| `id` | | если нет, строится из названия, адреса и сайта |

Повторный импорт того же файла дублей не создаёт. `--tag` отличает источники друг от друга.

## Что не подходит

- **Яндекс «Поиск по организациям»**: по условиям данные можно использовать только для показа на Яндекс Картах, строить базу нельзя.
- **Парсинг сайта 2gis.ru**: нарушает пользовательское соглашение 2GIS, ломается при изменении сайта и блокируется.

## Чем можно дополнить

- **Чекко** и **Контур.Поиск клиентов**: юрлица по региону и ОКВЭД с контактами (сайт, телефон, почта). Выгрузка в CSV грузится командой `import`.
  Условия и тарифы проверяйте на сайтах сервисов.
